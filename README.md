# P2P ファイル転送

ブラウザだけで動く、マルチプラットフォームな P2P ファイル送受アプリです。
[PeerJS](https://peerjs.com/)（WebRTC）を使い、接続後のファイル転送は端末間で直接行われます。

## 動かし方

`index.html` をブラウザで開くだけです（Chrome / Edge / Firefox / Safari、PC・スマホいずれも可）。

```bash
# ネットワーク上の別端末と試す場合（同じ LAN 内の端末からアクセス）
python3 -m http.server 8000
# → http://<このPCのIP>:8000/
```

## 使い方

1. 両方の端末でこのページを開く
2. 片方の「自分のコード」をもう片方に入力して「接続」
3. ファイルまたはフォルダをドラッグ＆ドロップ（またはボタンで選択）して送信
4. 相手側で「受け取る」を押すと受信が始まり、完了後に保存できます

- 2つ以上のファイル・フォルダを選ぶと、デフォルトで1つのZIP（無圧縮・ストア）にまとめて送信します。受信側は保存ボタン1回で受け取れ、解凍は各OSの標準機能で可能です。フォルダ構造はそのままZIP内の階層として保たれます（日本語ファイル名対応）
  - 梱包作業は**送信側・受信側のどちらがやるか選べます**（設定は記憶されます）。リソースに余裕がある側に寄せると快適です
    - **送信側がやる（既定）**：チェックサム計算と梱包を送信端末で行います。できあがるZIPの互換性が最も高い一方、送信端末に負荷がかかります（ファイルを2回読みます）
    - **受信側がやる**：送信端末はチェックサム計算なしでファイルをそのまま流すだけ（読み直しもなし）。古いスマホなど送信側が遅いときに推奨。受信側が届いたデータからチェックサムを計算しながらZIPを組み立て、最後に保存ボタン1回になります。両方の端末が最新版のページである必要があります
  - 「複数のファイル・フォルダは1つのZIPにまとめて送信」のチェックを外すと従来どおりの個別送信になります（フォルダは中身ごと送信され、受信側でファイルごとに保存ボタンが出ます。フォルダ構造は `_` 区切りのファイル名になります）
- 転送状況には実速度（MB/s）が表示されます。本来のLAN速度が出ているかの切り分けに使えます
- ファイルの読み出しは先読みパイプライン（最大4チャンク並行）+ 大きめチャンクで行われ、ストレージ読み出しが遅い端末でも速度が出やすくなっています
- 合計1GBを超える大量転送は、自動で1GB以下のZIP複数個（`フォルダ名-1of20.zip` のような名前）に分割して送ります。各パートは単体で正当なZIPです。受信側は最初のパートを承認すれば以降は自動受信し、メモリ使用量は1パート分程度に抑えられます
- 「自分のコード」の下にQRコードが表示されます。相手の端末（スマホのカメラ等）でスキャンすると、コード入力なしでページが開いて自動接続します（LAN提供時。`file://` 直接起動ではリンクにならないため手入力してください）
- 転送は WebRTC（DataChannel）のため、仕様上ピア間で常にDTLS暗号化されます。平文では流れません
- `?peer=コード` を URL につけると、相手コードが自動入力されそのまま接続します（QRの中身もこの形式です）
- トラブル時は `?debug=1` で開くと、コンソールから `__p2p.state()` / `__p2p.sendEntries(...)` で診断できます

## 注意

- 自分のコードの発行と相手の発見には PeerJS のパブリックシグナリングサーバー（0.peerjs.com）を使うため、**初回接続にはネット接続が必要**です
- 転送自体はピア間直接（WebRTC）で行われます。接続確立には通常、外部にファイル内容は送信されません
- 相手コードを知っている人だけが接続できますが、コードは推測可能な短さなので、機密ファイルの送信には注意してください
- QRコードには接続用URL（コード含む）が入っています。画面を見られる相手にしか渡りませんが、スクリーンショットの共有は避けてください
- ファイルの受け取りは常に承認制です。QRをスキャンされて接続されても、承認しない限りファイルは送信されません
- 受信したデータは保存ボタンを押すまでメモリに保持されるため、合計サイズが非常に大きい転送はメモリに余裕がある端末で行ってください（受信側梱包モードも同様）。1ファイルで1GBを超えるものは分割できないため、そのファイル分のメモリが必要です
- 画面オフやバックグラウンド化で転送が遅くなる端末があります。転送中はアプリが画面の自動オフを抑制します（Wake Lock対応ブラウザのみ）。遅い場合は画面を表示したまま試してください
- スリープ・画面消灯での切断対策として、転送中は無音オーディオ再生で処理の絞り込みを抑制します（ベストエフォート）。さらに切断された場合は同じ相手へ自動再接続し、中断したパートを自動で再送します（受信側がそのパートを保存していなかった場合に限る形の簡易復帰です。長時間のスリープでは、画面をできるだけオンにしたままが最も確実です）
- 分割転送のパートは、保存ボタンを押してから約2分後にメモリを解放します。大量転送中は届いたパートから早めに保存してください
- 梱包モードを変えても速度が低い場合（例: 4MB/s前後で頭打ち）は、まず送信端末のインターネット上り速度をスピードテスト等で測ってください。それと同程度なら、アプリではなくWi-Fiリンク自体が天井です（2.4GHz帯・電波が弱い・混雑）。ルーターに近づく、5GHz帯に接続する、で改善する可能性があります
